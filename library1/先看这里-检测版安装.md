# 狭间图书馆 v10：资源有效性检测

完整源码已包含站内提醒、分类、账号管理和樱花界面。
本版不是上传网页就会自动检测，还需要开启 GitHub 后台任务。

## 1．升级数据库
在 Supabase → SQL Editor → New query 中，运行 `06-validity.sql` 全文。
如果尚未安装上一版站内提醒，先执行 `05-reminders.sql`。
已有资源不会被删除。全新数据库才用完整 `database.sql`。

## 2．更新网页
将 `index.html`、`app.js`、`style.css` 覆盖原文件；如果上一版提醒也没有更新，另覆盖 `notifications.js`。
保留原 config.js 和已有其他文件。
将本包 `checker` 文件夹上传到网页目录，也就是仓库中的 `library/checker/check.py`。

## 3．添加后台任务（注意位置）
把本包“仓库根目录”文件夹里的 `.github` 文件夹，放到 GitHub 仓库最外层。
最终路径必须是 `.github/workflows/check-resources.yml`，不能放到 `library/.github`。
隐藏文件夹不容易上传时，可在 GitHub 点 Add file → Create new file，文件名直接填写 `.github/workflows/check-resources.yml`，粘贴本包同名文件内容并保存到默认分支。
任务最后一行默认运行 `python library/checker/check.py`。若你的网页文件直接在仓库根目录，改成 `python checker/check.py`。

## 4．只需设置一次的两个密钥
在 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret，创建：

| 名称（严格一致） | 内容 |
| --- | --- |
| SUPABASE_URL | 你现有 config.js 里的 Supabase 项目 URL |
| SUPABASE_SERVICE_ROLE_KEY | Supabase 项目 API Keys 中的旧版 service_role 密钥 |

第二项不能用网页的 anon key。service_role 只能放 GitHub Secrets，不能写进 config.js、源码或截图公开。无需把密钥发给任何人。
网页继续使用原来的 anon key。

## 5．首次运行
GitHub 仓库 → Actions → “检测资源有效性” → Run workflow → Run workflow。
如果没有任务，检查工作流是否位于默认分支和仓库根目录。
运行完成后刷新网站。任务日志只输出检测数量，不输出分享链接、提取码或后台密钥。

默认每日运行一次，每轮最多 80 条：未检测优先；正常自动结果每 7 天重检；待核验约每日重试。
手动运行勾选 force，可重检自动结果。每次结果逐条保存，中断后已经完成的结果仍保留。
Actions 定时运行可能延迟或被平台停用，需要时可以手动运行。
GitHub 与 Cloudflare 共用 Supabase 时，只需一份检测任务，两站都会看到同样结果。

## 显示与判断
- 有效：右上角透明底长方形印章，红色方框和“有效”二字。
- 无效：同样印章，灰色方框和“无效”二字。
- 待核验／待检测：小字标签，不冒充有效或无效印章。
- 点击印章可查看检查时间、自动或人工来源、原因。

一条资源只展示一个总结果；只检测填写的链接，遇到一个可用链接就停止。
所有链接都明确失效才标无效；有未知情况则保留待核验。
提取码读取顺序：单独填写的码 → URL 中的 pwd/password/passcode → 单链接资源备注里的明确提取码。
多链接资源不会猜测备注中不明确归属的密码。其他链接字段若填百度或夸克地址，也能按域名识别。
百度检测会尝试在提取码页面自动填码并提交；必须获得文件列表数据才判有效。
夸克检测会用提取码取得分享访问令牌，再读取文件列表。拿到令牌本身不代表有效。
其他站点暂不通用判断，可由管理员人工核验；打不开或 HTTP 200 都不能直接说明资源失效／有效。

## 管理员手工纠正
卡片上“核验状态”可设有效／无效／待核验／重新自动检测，并填写说明。
手动结果不会被定时程序覆盖；选择“重新自动检测”或作者修改链接／提取码／备注后恢复自动检查。
更改分类或标题不会撤销印章。后台检测结果基于版本和检测修订号写入，过期结果不会盖到新链接上。
“重新自动检测”是排队，非立即执行；可接着在 GitHub Actions 手动运行。
检查结果不会自动删除资源或发送提醒。需要联系上传者时仍点击“提醒上传者”。
